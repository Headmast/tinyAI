# Руководство по устранению неполадок (Troubleshooting)

## Диагностика проблем

### Пошаговая диагностика

При возникновении проблемы выполните:

1. **Проверьте статус платформы:** https://status.tinyai.example.com
2. **Проверьте свой тариф и лимиты:** Настройки → Подписка → Использование
3. **Проверьте API-ключ:** Настройки → API → убедитесь, что ключ активен
4. **Проверьте логи:** в панели управления → Запросы → Логи

## Проблемы с авторизацией

### Ошибка «Invalid credentials»

**Причины:**
- Неверный email или пароль
- Аккаунт не подтверждён (не перешли по ссылке из email)
- Caps Lock включён

**Решение:**
1. Проверьте правильность email (регистр не важен)
2. Сбросьте пароль через «Забыли пароль?»
3. Если не получали письмо подтверждения — запросите повторно на странице входа

### Ошибка «Account locked»

**Причины:**
- 5+ неудачных попыток входа подряд
- Подозрительная активность обнаружена системой безопасности

**Решение:**
- Подождите 30 минут (автоматическая разблокировка)
- Или перейдите по ссылке из email «Разблокировка аккаунта»
- Если аккаунт заблокирован системой безопасности — обратитесь в поддержку

### Ошибка «Token expired» (401)

**Причины:**
- Прошло более 24 часов с момента входа
- Сессия была аннулирована (смена пароля, выход со всех устройств)

**Решение:**
- Выполните повторный вход
- Для API: используйте refresh token или получите новый access token
- Проверьте часы на устройстве (расхождение > 5 минут может вызвать проблему)

### 2FA не работает

**Причины:**
- Время на устройстве расходится с серверным (TOTP зависит от времени)
- Приложение-аутентификатор перестало работать
- Потеряно устройство

**Решение:**
1. Синхронизируйте время на телефоне (автоматическое время)
2. Подождите 30 секунд и используйте новый код
3. Используйте один из резервных кодов (10 выданы при настройке 2FA)
4. Если резервные коды утеряны — обратитесь в поддержку с подтверждением личности

## Проблемы с API

### Ошибка 401 Unauthorized

**Диагностика:**
```bash
curl -I https://api.tinyai.example.com/v1/projects \
  -H "Authorization: Bearer YOUR_KEY"
```

**Причины и решения:**
- Ключ скопирован неполностью → создайте новый ключ
- Ключ удалён → создайте новый в Настройки → API
- Формат заголовка неверный → `Authorization: Bearer <key>` (с пробелом после Bearer)
- Ключ от другого окружения (staging/production)

### Ошибка 429 Too Many Requests

**Диагностика:**
- Заголовок ответа `X-RateLimit-Remaining: 0` — лимит исчерпан
- Заголовок `Retry-After: 45` — ждать N секунд

**Причины:**
- Превышен rate limit (Free: 10 req/min, Pro: 60 req/min, Enterprise: 300 req/min)
- Бёрст запросов (много запросов одновременно)

**Решения:**
1. Добавьте задержку между запросами (минимум 1 секунда)
2. Реализуйте exponential backoff: 1s → 2s → 4s → 8s
3. Проверьте, нет ли бесконечного цикла в коде
4. Обновите тариф для большего лимита
5. Enterprise: запросите увеличение индивидуального лимита

### Ошибка 500 Internal Server Error

**Решения:**
1. Повторите запрос через 30 секунд
2. Уменьшите размер запроса (текст < 10KB)
3. Проверьте статус платформы
4. Если проблема повторяется > 5 минут — создайте тикет

### Ошибка 413 Payload Too Large

**Причины:**
- Запрос > 10 MB (Pro) или > 50 MB (Enterprise)
- Документ для загрузки слишком большой

**Решение:**
- Разбейте файл на части (< 5 MB рекомендуемый размер)
- Удалите бинарные данные / изображения из документа

### Таймаут запроса (504 Gateway Timeout)

**Причины:**
- Запрос выполняется > 30 секунд
- Слишком большой `top_k` (> 20)
- Индекс > 100K чанков и нет reranker'а

**Решения:**
1. Уменьшите `top_k` до 3-5
2. Используйте конкретную стратегию вместо `both`
3. Упростите запрос (короткие запросы обрабатываются быстрее)
4. Разделите большой проект на несколько меньших

## Проблемы с оплатой

### Карта отклонена

**Возможные причины:**
- Недостаточно средств на карте
- Банк заблокировал онлайн-платёж
- Истёк срок действия карты
- Карта не поддерживает рекуррентные платежи

**Решения:**
1. Проверьте баланс и лимиты в мобильном банке
2. Разрешите интернет-платежи и рекуррентные списания
3. Попробуйте другую карту
4. Для карт МИР: включите онлайн-платежи в настройках карты

### Двойное списание

**Действия:**
1. Не паникуйте — часто это авторизационный холд (заморозка), а не реальное списание
2. Подождите 3-5 рабочих дней — холд должен отмениться автоматически
3. Если через 5 дней деньги не вернулись — создайте тикет с датами и суммами
4. Мы инициируем возврат в течение 5-10 рабочих дней

### Не применился промокод

**Проверьте:**
- Промокод введён ДО нажатия кнопки оплаты
- Срок действия промокода не истёк
- Промокод применим к вашему тарифу (некоторые только для Pro)
- Один промокод = один аккаунт (повторно использовать нельзя)

## Проблемы с интеграциями

### Вебхук не доставляется

**Диагностика:**
1. Настройки → Интеграции → Вебхуки → Логи доставки
2. Проверьте статус последних попыток доставки

**Типичные ошибки в логах:**

| Статус | Причина | Решение |
|---|---|---|
| `ssl_error` | Невалидный SSL-сертификат | Используйте Let's Encrypt или купите сертификат |
| `timeout` | Сервер не ответил за 10с | Оптимизируйте обработку вебхука |
| `connection_refused` | Порт закрыт | Проверьте файрвол и настройки сервера |
| `http_4xx` | Ваш сервер вернул ошибку | Проверьте код обработчика |
| `http_5xx` | Ваш сервер упал | Проверьте логи вашего сервера |

**Важно:** вебхук-эндпоинт должен вернуть 200 OK в течение 10 секунд. Иначе доставка считается неудачной, и будет retry (3 попытки с интервалом 1 мин, 5 мин, 30 мин).

### Telegram-бот не отвечает

**Проверьте:**
1. Бот запущен: отправьте `/start` боту @TinyAIBot
2. Проект привязан: `/connect PROJECT_ID`
3. Бот имеет доступ к чату (добавлен в группу с правами)

**Перезагрузка:** `/restart` → `/connect PROJECT_ID`

### Slack-интеграция не работает

**Решения:**
1. Переустановите приложение из Slack App Directory
2. Проверьте scopes: `chat:write`, `channels:read`, `commands`
3. Убедитесь, что приложение добавлено в нужный канал (`/invite @TinyAI`)

## Проблемы с производительностью

### Медленные запросы

**Бенчмарк нормальной производительности:**
- Простой запрос (top_k=5): 1-3 секунды
- Запрос с реранкингом: 3-5 секунд
- Запрос с citations: 2-4 секунды

**Если запросы медленнее:**
1. Уменьшите `top_k` (рекомендуется 3-5)
2. Используйте `strategy: "structure"` вместо `"both"`
3. Проверьте размер индекса — если > 50K чанков, рассмотрите разделение проекта
4. Время суток: пиковая нагрузка 10:00-14:00 MSK

### Медленная индексация

**Ускорение:**
1. Загружайте документы батчами по 20-50 штук
2. Документы > 1 MB разбейте на части
3. Удалите бинарные / нетекстовые данные из файлов
4. Используйте формат Markdown (быстрее парсится)

## Проблемы с данными

### Случайно удалили документ

**Восстановление:**
1. Перейдите в Корзину (значок корзины на панели документов)
2. Найдите документ (хранится 30 дней)
3. Нажмите «Восстановить»
4. Документ будет переиндексирован автоматически (1-2 минуты)

### Индекс устарел после обновления документов

**Решение:**
1. Настройки проекта → «Переиндексировать»
2. Или через API: `POST /v1/reindex`
3. Автоматическая переиндексация: включите в Настройки → Проект → Авто-переиндексация

### Конфликт версий при совместном редактировании

**Что делать:**
1. Система покажет обе версии
2. Выберите «Мою версию» или «Версию коллеги»
3. Или: «Объединить» — откроется diff-view
4. Рекомендация: договоритесь о зонах ответственности в команде
