# Руководство по продукту TinyAI Platform

## Обзор платформы

TinyAI Platform — облачная платформа для работы с AI-моделями через RAG (Retrieval-Augmented Generation). Позволяет загружать документы, строить индексы и задавать вопросы по вашим данным.

## Основные возможности

### RAG-запросы

RAG (Retrieval-Augmented Generation) — технология, которая позволяет AI отвечать на вопросы, используя ваши документы как источник знаний.

**Как это работает:**
1. Вы загружаете документы (PDF, Markdown, TXT)
2. Платформа автоматически индексирует их (разбивает на чанки, создаёт эмбеддинги)
3. При запросе система находит релевантные фрагменты и генерирует ответ

**Параметры запроса:**
- `query` — текст вопроса
- `top_k` — количество источников для ответа (по умолчанию 5)
- `strategy` — стратегия поиска: `structure` (по заголовкам) или `fixed_size` (фиксированные окна)

### Проекты

Проект — это изолированное пространство с документами и настройками.

**Создание проекта:**
1. Перейдите на панель управления
2. Нажмите «Новый проект»
3. Укажите название и описание
4. Выберите стратегию индексации

**Лимиты проектов по тарифу:**
- Free: 1 проект
- Pro: 10 проектов
- Enterprise: без ограничений

### Документы

**Поддерживаемые форматы:**
- Markdown (.md) — рекомендуемый формат, сохраняет структуру заголовков
- Plain text (.txt) — простой текст без форматирования
- PDF (.pdf) — извлекается текстовый слой
- DOCX (.docx) — конвертируется в текст
- HTML (.html) — извлекается текстовое содержимое

**Рекомендации по структуре документов:**
- Используйте заголовки (# ## ###) для разделения тем
- Один документ — одна тема (для лучшей релевантности)
- Оптимальный размер: 500-5000 слов на документ
- Избегайте таблиц с данными без контекста

### Индексация

**Стратегии индексации:**

| Стратегия | Описание | Когда использовать |
|---|---|---|
| `structure` | Разбивает по заголовкам Markdown | Структурированные документы |
| `fixed_size` | Фиксированные окна по 512 токенов | Неструктурированный текст |
| `both` | Обе стратегии | Максимальное покрытие |

**Процесс индексации:**
1. Чанкинг — разбивка документа на фрагменты
2. Эмбеддинг — векторизация каждого фрагмента (text-embedding-3-small)
3. Сохранение — FAISS-индекс + SQLite метаданные

**Время индексации:**
- 1-10 документов: 5-30 секунд
- 10-100 документов: 1-5 минут
- 100-1000 документов: 5-30 минут

### API

**Базовый URL:** `https://api.tinyai.example.com/v1`

**Эндпоинты:**

| Метод | URL | Описание |
|---|---|---|
| POST | `/query` | RAG-запрос по документам |
| POST | `/documents` | Загрузка документа |
| GET | `/documents` | Список документов |
| DELETE | `/documents/{id}` | Удаление документа |
| POST | `/reindex` | Переиндексация проекта |
| GET | `/projects` | Список проектов |
| GET | `/usage` | Статистика использования |

**Пример запроса:**
```bash
curl -X POST https://api.tinyai.example.com/v1/query \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Как настроить вебхук?",
    "top_k": 5,
    "strategy": "structure",
    "project_id": "proj_123"
  }'
```

**Пример ответа:**
```json
{
  "answer": "Для настройки вебхука перейдите в...",
  "sources": [
    {"section": "Интеграции > Вебхуки", "score": 0.89},
    {"section": "API > Вебхуки", "score": 0.72}
  ],
  "tokens_used": 450,
  "elapsed_ms": 1200
}
```

## Безопасность

### Шифрование данных

- Данные в покое: AES-256
- Данные в движении: TLS 1.3
- API-ключи: хэшируются при хранении

### Аутентификация

- Пароли: bcrypt с salt
- Сессии: JWT с 24-часовым сроком
- 2FA: TOTP (RFC 6238)
- OAuth: Google, GitHub

### Изоляция данных

- Данные каждого проекта хранятся в изолированном namespace
- Нет доступа между проектами разных пользователей
- Enterprise: dedicated instance (отдельный сервер)

## Часто задаваемые технические вопросы

### Как работает поиск?

1. Запрос пользователя конвертируется в вектор (эмбеддинг)
2. FAISS ищет ближайшие векторы среди всех чанков (cosine similarity)
3. Найденные чанки ранжируются (опционально: LLM-реранкинг)
4. Top-K чанков отправляются в LLM как контекст
5. LLM генерирует ответ с цитированием источников

### Почему ответ неточный?

Возможные причины:
- Документация не содержит нужной информации
- Запрос сформулирован неоднозначно (перефразируйте)
- Устаревшие документы (переиндексируйте)
- Низкий score у результатов (добавьте больше документации по теме)

### Как улучшить качество ответов?

1. Добавьте больше документации по теме
2. Структурируйте документы с заголовками
3. Используйте конкретные формулировки в запросах
4. Увеличьте `top_k` для большего контекста
5. Попробуйте стратегию `both` для лучшего покрытия
