## Детальный план по шагам

### Шаг 1. Базовый класс `ContextStrategy` + `SlidingWindowStrategy`

**Файл: `news_agent/context_strategies.py`**

```python
class ContextStrategy(ABC):
    """Базовый класс стратегии управления контекстом."""
    name: str
    
    @abstractmethod
    def get_messages_for_api(self, messages, system_prompt) -> List[Dict]
    
    @abstractmethod
    def on_user_message(self, user_msg, all_messages) -> None
    
    def get_stats(self) -> Dict[str, Any]
    
    def to_dict(self) -> Dict  # сериализация
    
    @classmethod
    def from_dict(cls, data) -> "ContextStrategy"  # десериализация
```

**SlidingWindowStrategy:**
- Параметр `window_size: int = 10` (количество последних сообщений)
- `get_messages_for_api()` → `[system] + messages[-window_size:]`
- Всё что за окном — отбрасывается
- Статистика: сколько сообщений отброшено, сколько токенов в окне

### Шаг 2. `StickyFactsStrategy` (Key-Value Memory)

- Отдельный словарь `facts: Dict[str, str]` (ключ-значение)
- После каждого сообщения пользователя — LLM-вызов для извлечения/обновления фактов
- Категории фактов: цель, ограничения, предпочтения, решения, договорённости, технические детали
- `get_messages_for_api()` → `[system] + [facts_block] + messages[-N:]`
- `facts_block` — системное сообщение с форматированными фактами
- Параметры: `window_size=6` (последние сообщения), `max_facts=20`

**Промпт для извлечения фактов:**
```
Проанализируй последнее сообщение пользователя в контексте диалога.
Извлеки/обнови ключевые факты в формате JSON:
{"цель": "...", "ограничения": "...", ...}
Верни ТОЛЬКО JSON, без пояснений.
```

### Шаг 3. `BranchingStrategy` (ветки диалога)

- `checkpoints: Dict[str, List[Dict]]` — именованные точки сохранения
- `branches: Dict[str, List[Dict]]` — ветки от checkpoint'ов
- `current_branch: str` — текущая активная ветка ("main" по умолчанию)
- Команды:
  - `branch save <name>` — создать checkpoint
  - `branch create <name> [from_checkpoint]` — создать ветку
  - `branch switch <name>` — переключиться на ветку
  - `branch list` — список веток и checkpoint'ов
  - `branch diff <a> <b>` — показать различия между ветками
- `get_messages_for_api()` → сообщения текущей ветки
- Каждая ветка хранит свою независимую историю от точки ветвления

### Шаг 4. Переключатель стратегий

**В `ConversationSession`:**
- Новое поле: `context_strategy: Optional[ContextStrategy]`
- Модификация `get_messages_for_api()`:
  ```python
  if self.context_strategy:
      return self.context_strategy.get_messages_for_api(self.messages, self.system_prompt)
  # fallback к существующей логике (compression / full history)
  ```
- Метод `set_strategy(strategy_name, **params)`
- Сериализация стратегии в `to_dict()` / `from_dict()`

**В `_run_chat_loop()` — новые команды:**
- `strategy` — показать текущую стратегию
- `strategy sliding [N]` — включить Sliding Window
- `strategy facts [N]` — включить Sticky Facts
- `strategy branching` — включить Branching
- `strategy off` — выключить стратегию (полная история)
- `branch save/create/switch/list/diff` — управление ветками

## Критический взгляд на архитектурные решения

**Потенциальные проблемы:**

1. **StickyFacts — LLM-вызов на каждое сообщение:** Удваивает количество API-вызовов. Контраргумент: это _дешёвый_ вызов (короткий промпт, ~200 токенов ответа), а экономия на основном контексте может перевесить.

2. **Branching — рост хранилища:** Каждая ветка дублирует историю от checkpoint. Решение: хранить только дельту (сообщения после точки ветвления), а общую часть — по ссылке.

3. **Sliding Window — жёсткая потеря:** Нет механизма "важности" — отбрасывается всё одинаково. Это сознательный trade-off: простота vs качество.

4. **Тестирование с LLM:** Результаты недетерминированы. Решение: фиксированный seed/temperature=0 (если модель поддерживает), + запуск 2-3 раза для статистической значимости.
