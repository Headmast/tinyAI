# Рабочий процесс (Workflow)

Стандартный флоу работы над каждым заданием курса TinyAI.

## Цикл разработки

```
┌─────────────────┐
│  1. ПОСТАНОВКА   │  Формулировка задачи: что нужно сделать
│     ТРЕБОВАНИЙ   │
└────────┬────────┘
         ▼
┌─────────────────┐
│  2. АНАЛИЗ       │  Изучение существующего кода, зависимостей,
│     ТРЕБОВАНИЙ   │  ограничений и контекста
└────────┬────────┘
         ▼
┌─────────────────┐
│  3. ДОПОЛНЕНИЕ   │  Уточнение требований, добавление edge-cases,
│     ТРЕБОВАНИЙ   │  определение границ задачи
└────────┬────────┘
         ▼
┌─────────────────┐
│  4. ПЛАН         │  Декомпозиция: файлы, классы, функции,
│     РЕАЛИЗАЦИИ   │  порядок создания, зависимости
└────────┬────────┘
         ▼
┌─────────────────┐
│  5. РЕАЛИЗАЦИЯ   │  Написание кода по плану
│     В КОДЕ       │
└────────┬────────┘
         ▼
┌─────────────────┐
│  6. ТЕСТИРОВАНИЕ │  Написание и запуск тестов
│                  │
└────────┬────────┘
         ▼
┌─────────────────┐     ┌────────────────┐
│  7. ПРОВЕРКА     │──▶  │ 8. ИСПРАВЛЕНИЕ │
│                  │     │    ОШИБОК      │
└────────┬────────┘     └───────┬────────┘
         │                      │
         │    ◄─────────────────┘  (цикл до зелёных тестов)
         ▼
┌─────────────────┐
│  9. ФИНАЛЬНАЯ    │  Все тесты проходят, код ревью,
│     ПРИЁМКА      │  коммит в ветку задания
└─────────────────┘
```

## Принципы

- **Итеративность** — цикл «код → тест → исправление» повторяется до стабильного результата
- **Тесты до коммита** — не коммитить код с падающими тестами
- **Инкрементальность** — каждое задание строится поверх предыдущих
- **Документация** — каждое задание резюмируется в `docs/workflow/`
