## 2. Что оптимизируем

### 2.1 Параметры генерации

**Temperature** — контролирует «случайность» ответа:
- Для RAG задач нужна **низкая temperature** (0.0–0.3): ответ должен быть точным, основанным на контексте
- Слишком высокая → галлюцинации, отход от фактов документов
- **Тестируем:** 0.0, 0.1, 0.3, 0.5, 0.7

**Max tokens** — максимальная длина ответа:
- Слишком мало → обрезанные ответы, потерянные цитаты
- Слишком много → модель «размазывает» ответ, лишние расходы
- **Тестируем:** 800, 1200, 2000, 3000

**Top-p (nucleus sampling)** — порог вероятности для выбора токенов:
- Ниже → более предсказуемые ответы
- Выше → разнообразнее
- **Тестируем:** 0.7, 0.8, 0.9, 1.0

**Qwen3 /nothink** — суффикс, отключающий внутреннее рассуждение модели:
- Без него: модель тратит токены на `<thinking>` → медленнее, больше потребление
- С ним: прямой ответ, быстрее, экономия контекста
- **Тестируем:** с /nothink vs без

### 2.2 Квантование

Квантование уменьшает точность весов модели, снижая потребление RAM и увеличивая скорость:

| Вариант | Точность | Ожидаемый RAM | Скорость | Качество |
|---------|----------|---------------|----------|----------|
| `qwen3:8b` | FP16 (16-bit) | ~8 GB | Baseline | Baseline |
| `qwen3:8b-q8_0` | INT8 (8-bit) | ~5 GB | Быстрее | ~Равное |
| `qwen3:8b-q4_K_M` | INT4 (4-bit) | ~3.5 GB | Самый быстрый | Снижение |

### 2.3 Промпт-шаблон

**Оригинальный промпт** (для GLM-4.7, 128K контекст):
- Развёрнутые инструкции с Markdown форматированием
- Множество правил и примеров
- ~600 токенов системного промпта

**Оптимизированный промпт** (для Qwen3 8B, 32K контекст):
- Короче, директивнее (маленькие модели лучше следуют кратким инструкциям)
- Без лишнего форматирования
- ~200 токенов системного промпта
- Экономия ~400 токенов = больше места для контекста документов

## 3. Методология бенчмарка

### Тестовые вопросы

| ID | Тип | Описание |
|----|-----|----------|
| factual_1 | Фактический | Компоненты RAG-архитектуры TinyAI |
| factual_2 | Фактический | MCP Agent и его инструменты |
| multihop_1 | Multi-hop | Fast mode vs standard mode в RAG |
| detail_1 | Детальный | Рекомендации по temperature |
| synthesis_1 | Синтез | Полный цикл journalist FSM agent |

### Метрики

- **Время ответа** (секунды) — от запроса до полного ответа
- **TTFT** (Time To First Token) — задержка до первого токена
- **Tokens/sec** — скорость генерации
- **Keyword score** — доля ожидаемых ключевых слов в ответе (0–100%)
- **Citation rate** — % ответов с цитатами в формате «»
- **Source rate** — % ответов с блоком источников [N]
- **RAM** — потребление памяти процессом

### Фазы бенчмарка

1. **params** — grid search по temperature, max_tokens, top_p, /nothink
2. **quant** — сравнение fp16 vs q8_0 vs q4_K_M
3. **prompts** — оригинальный vs оптимизированный промпт
4. **combined** — лучшая конфигурация на всех квантизациях

## 4. Запуск бенчмарка

```bash
# Подготовка: скачать квантованные модели

# Полный бенчмарк (все фазы)
```

## 7. Выводы

### Ожидаемые улучшения

1. **Temperature 0.1** vs baseline 0.4 → меньше галлюцинаций, точнее цитаты
2. **/nothink** → ~2x ускорение (нет overhead на reasoning)
3. **Оптимизированный промпт** → ~400 токенов экономии в системном промпте = больше контекста для RAG
4. **Q8_0 квантование** → ~40% экономия RAM при минимальной потере качества
5. **Q4_K_M** → ~60% экономия RAM, заметное снижение качества (для быстрых задач)

### Трейдоффы

| Оптимизация | Плюсы | Минусы |
|-------------|-------|--------|
| Низкая temperature | Точность, воспроизводимость | Менее живой стиль |
| /nothink | Скорость, экономия токенов | Нет chain-of-thought для сложных вопросов |
| Короткий промпт | Экономия контекста | Менее гибкий формат |
| Q8_0 | RAM, скорость | Минимальная потеря качества |
| Q4_K_M | Минимум RAM, максимум скорости | Заметная потеря качества |
