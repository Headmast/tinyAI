# Task 2: Сравнение форматов ответов и логирование

## Описание задания

В этом задании реализованы следующие возможности:

1. **Переключение между режимами работы в реальном времени**
2. **Переключение между моделями OpenAI с автоматическим расчетом стоимости**
3. **Отправка одного запроса с разными параметрами форматирования**
4. **Сравнение ответов с ограничениями и без**
5. **Логирование всех вопросов и ответов с трекингом токенов и слов**

## Новые возможности

### 1. Переключение режимов

Утилита поддерживает 5 режимов работы с возможностью переключения в процессе диалога:

#### Режим 1: Без ограничений (по умолчанию)
- Стандартный запрос без дополнительных параметров
- Базовая температура 0.7
- Нет ограничений на длину ответа

#### Режим 2: С явным форматом ответа
- **Системный промпт**: Структурирует ответ по разделам:
  - ОСНОВНОЙ ОТВЕТ (подробный ответ)
  - КРАТКОЕ РЕЗЮМЕ (1-2 предложения)
  - КЛЮЧЕВЫЕ МОМЕНТЫ (список из 2-3 пунктов)
- Демонстрирует структурированный текстовый вывод

#### Режим 3: С ограничением длины
- **Системный промпт**: "Отвечай предельно кратко и лаконично. Максимум 50 слов"
- **max_tokens**: 100
- Показывает влияние двойного ограничения (токены + промпт)
- Трекает соответствие ограничению по словам

#### Режим 4: С условием завершения (stop sequence)
- **Системный промпт**: "После завершения ответа обязательно добавь маркер [КОНЕЦ]"
- **stop**: ["[КОНЕЦ]"]
- Демонстрирует API-параметр остановки генерации
- Маркер не включается в финальный ответ

#### Режим 5: С выводом в формате JSON
- **Системный промпт**: Требует строгий JSON-формат с полями:
  - `answer` - подробный ответ на вопрос
  - `summary` - краткое резюме в 1-2 предложения
  - `key_points` - массив из 2-3 ключевых моментов
- Возвращает только валидный JSON, без дополнительного текста
- Удобен для программной обработки ответов

### 2. Команды управления

**`modes`** - показать список всех доступных режимов с их описанием

**`mode N`** - переключиться на режим N (где N = 1, 2, 3, 4 или 5)
- Пример: `mode 3` - переключение на режим с ограничением длины
- Пример: `mode 5` - переключение на JSON-формат

**`compare`** - запустить сравнение всех режимов на одном запросе

**`models`** - показать список всех доступных моделей с ценами

**`model <name>`** - переключиться на другую модель
- Пример: `model gpt-4o-mini` - переключение на самую экономичную модель
- Пример: `model gpt-4` - переключение на самую мощную модель

### 3. Автоматическое логирование с расширенной статистикой

Все взаимодействия автоматически сохраняются в папке `logs/`:

**Структура лога:**
```json
[
  {
    "timestamp": "2026-03-17T18:30:45.123456",
    "user_input": "Вопрос пользователя",
    "assistant_response": "Ответ ассистента",
    "usage": {
      "prompt_tokens": 50,
      "completion_tokens": 100,
      "total_tokens": 150,
      "word_count": 45,
      "cost": 0.000275
    },
    "metadata": {
      "mode": "normal"
    }
  }

```

**Имя файла**: `conversation_YYYYMMDD_HHMMSS.json`

**Новые метрики в логах:**
- `word_count` - количество слов в ответе
- Позволяет анализировать соответствие ограничениям
- Помогает оценить информативность ответов

```bash
You: compare
Введите запрос для сравнения: Что такое машинное обучение?
```

После выполнения вы увидите:
1. Ответы во всех пяти режимах с их системными промптами
2. Детальную статистику для каждого режима:
   - Токены (prompt + completion)
   - Количество слов
   - Количество символов
   - Стоимость запроса
3. Сводную таблицу сравнения всех режимов
4. Анализ разброса стоимости и длины ответов

## Анализ результатов

При сравнении режимов обратите внимание на:

1. **Длину ответов в разных метриках**:
   - Символы (chars) - базовая метрика длины текста
   - Слова (words) - семантическая метрика информативности
   - Токены (tokens) - метрика для расчета стоимости

2. **Влияние системного промпта**:
   - Режим 2 добавляет структуру без ограничения длины
   - Режим 3 использует двойное ограничение (промпт + max_tokens)
   - Режим 4 демонстрирует stop sequence как API-параметр

3. **Соотношение токены/слова**:
   - В среднем 1 токен ≈ 0.75 слова для русского языка
   - Позволяет оценить эффективность кодирования

4. **Экономическая эффективность**:
   - Режим 3 обычно самый дешевый (ограничение длины)
   - Режим 1 самый дорогой (нет ограничений)
   - Режим 2 средний по стоимости (структура требует токенов)

## Технические детали

### Архитектура системы режимов

**`get_available_modes()`**
- Возвращает список конфигураций всех режимов
- Каждый режим содержит: id, name, params, system_prompt (опционально), metadata

**`execute_mode(client, mode, user_input)`**
- Универсальный исполнитель режима
- Формирует messages с системным промптом (если есть)
- Передает параметры в OpenAI API

**`count_words(text)`**
- Подсчитывает количество слов в тексте
- Использует split() для разделения по пробелам

**`interactive_mode_selection(client, user_input, log_file, mode_id)`**
- Выполняет запрос в выбранном режиме
- Логирует результат с метаданными режима
- Возвращает usage_info для учета в общей статистике

**`compare_formatting_modes(client, user_input, log_file)`**
- Отправляет 4 запроса с разными параметрами
- Собирает расширенную статистику (tokens, words, chars)
- Логирует все ответы
- Выводит сводку и анализ

### Функции логирования

**`setup_logging()`**
- Создает папку `logs/`
- Генерирует уникальное имя файла с timestamp

**`log_interaction(log_file, user_input, assistant_response, usage_info, metadata)`**
- Сохраняет каждое взаимодействие в JSON
- Добавляет метаданные о режиме работы
- Включает word_count в usage_info

## Команды

- `quit`, `exit`, `q` - выход из программы с итоговой статистикой
- `modes` - показать список всех режимов с отметкой текущего (★)
- `mode N` - переключиться на режим N (1-5)
- `models` - показать список всех моделей с ценами и отметкой текущей (★)
- `model <name>` - переключиться на другую модель OpenAI
- `compare` - запустить сравнение всех режимов на одном запросе
- Любой другой текст - запрос к LLM в текущем режиме

## Ключевые особенности реализации

1. **Логирование**:
   - Все логи сохраняются локально и не попадают в репозиторий
   - Каждая сессия создает отдельный лог-файл
   - В логах сохраняется word_count для всех взаимодействий

2. **Статистика сессии**:
   - Режим сравнения не учитывается в общей статистике
   - Учитываются только обычные запросы в выбранном режиме
   - При выходе показывается итоговая статистика

3. **Системные промпты**:
   - Формат ответа задается через system role, не через JSON
   - Stop sequence передается как API-параметр
   - Ограничение длины комбинирует max_tokens и промпт

4. **Автоматический расчет стоимости**:
   - Поддержка 5 моделей OpenAI с разными ценами
   - Автоматический пересчет при смене модели
   - См. MODELS_INFO.md для детального сравнения цен
