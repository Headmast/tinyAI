# Task 6 — News Agent CLI

> AI-агент для автоматической генерации новостных постов на базе LLM.  
> Два режима: **детерминированный 5-шаговый pipeline** и **автономный ReAct-агент** с function calling.

---

## Быстрый старт

```bash
# 1. Убедитесь что .env настроен (минимум один ключ)
cat .env
# CLOUD_API_KEY=...   или   OPENAI_API_KEY=...

# 2. Запустить демо без API (реалистичные фикстуры)
python3 demo_pipeline.py

# 3. Запустить интерактивный CLI
python3 llm_cli.py

# 4. Запустить тесты (72 теста, без API)
pytest test_news_agent.py test_llm_cli.py -v
```

```
llm_cli.py                   ← точка входа (CLI)
news_agent/
    __init__.py

    tools.py                 ← tool definitions + ToolDispatcher

```

## Два режима генерации

### 1. Pipeline (детерминированный, рекомендуется)

Последовательный конвейер из 5 этапов:

```
[1] PLANNER     → анализ темы, тип поста, угол подачи, структура
[2] RESEARCHER  → факты, статистика, контекст, ключевые участники
[3] WRITER      → написание черновика по плану и фактам
[4] EDITOR      → редактура, оценка качества (1-10), список правок
[5] SEO         → варианты заголовков, теги, мета-описание, хэштеги
```

Каждый этап — отдельный LLM-вызов с уникальным системным промптом и температурой.

### 2. Agent (автономный, ReAct-паттерн)

```
Thought → Action (tool call) → Observation → repeat → Final Answer
```

Агент сам решает порядок действий, вызывает инструменты через function calling API.

| `seo`        | 0.6         | Заголовки, теги, мета-описание                 |
| `autonomous` | 0.5         | Автономный агент (ReAct)                       |

## Команды CLI

```bash

```

| Команда                        | Описание                                |

## Качество вывода

Редактор (`editor`-роль) выставляет оценку по 4 критериям:

- **clarity** — понятность изложения
- **accuracy** — точность формулировок
- **engagement** — вовлечённость читателя
- **structure** — логическая структура

Итоговый `quality_score` — среднее из 4 критериев (1–10).

## Устройство компонентов

### `news_agent/roles.py` — Роли-персоны

Каждая роль — `dataclass Role(name, description, system_prompt, temperature)`.

Ключевые решения:
- `planner` и `editor` — низкая температура (0.3) → детерминированные JSON-ответы
- `writer` — высокая температура (0.75) → разнообразный стиль
- Каждая роль возвращает строго определённую JSON-схему (кроме writer)

### `news_agent/pipeline.py` — NewsPipeline

Оркестрирует 5 последовательных LLM-вызовов. Каждый шаг:
1. Берёт выход предыдущего шага как входной контекст
2. Использует свою роль и температуру
3. Парсит JSON-ответ с fallback на `raw_response` при сбое

**Важно:** pipeline не падает при некорректном JSON — сохраняет сырой ответ
и продолжает работу.

### `news_agent/agent.py` — AgentLoop (ReAct)

Цикл до `MAX_ITERATIONS = 12`:
```
messages → LLM → tool_calls → dispatch → observation → back to messages
```

Завершение: LLM пишет `FINAL_POST:` в ответе.

### `news_agent/tools.py` — ToolDispatcher

- Схемы (`TOOL_DEFINITIONS`) — для передачи в OpenAI API
- `ToolDispatcher` — диспатчер, делегирует вызовы в `PostStorage` и `OutputFormatter`
- Каждый инструмент возвращает JSON-строку (для протокола messages)

### `news_agent/storage.py` — PostStorage

```
posts/
  index.json            ← список {id, title, post_type, tags, created_at, word_count}
  <id>/
    post.json           ← полные данные
    post.md             ← Markdown автоматически
```

Поиск по похожести — пересечение ключевых слов (Jaccard-подобный).
В production заменить на векторный поиск (pgvector / FAISS).

## Известные ограничения и план развития

| Ограничение | Решение в следующей итерации |
|---|---|
| Нет реального web-поиска | Подключить Tavily API / DuckDuckGo |
| Поиск дублей по словам, не по смыслу | Векторные эмбеддинги |
| Нет веб-интерфейса | FastAPI + Jinja2 или Streamlit |
| Нет расписания (cron) | APScheduler / Celery beat |
| Нет публикации | Telegram Bot API / WordPress REST |
| Нет мультиязычности | Роль-переводчик + параметр `--lang` |
