# День 14. Инварианты и ограничения состояния

## Задача

Добавить в ассистента инварианты — жёсткие ограничения, которые он не имеет права нарушать.

**Предметная область**: журналистика.

**Инварианты редакции**:
- `INV-001` — не писать о художественной гимнастике
- `INV-002` — не писать о криминальной хронике

## Ключевые принципы

### Хранение отдельно от диалога
Инварианты хранятся в `journalist_agent/invariants.json` — независимо от истории диалога.
Это позволяет изменять инварианты «на ходу» без перезапуска агента (`store.reload()`).

### Явный учёт в рассуждениях
Инварианты инжектируются в начало `system prompt` как секция с наивысшим приоритетом.
LLM видит каждый инвариант, его обоснование и инструкцию по отказу.

### Отказ при нарушении
- **Pre-check**: мгновенный отказ по ключевым словам (без расхода токенов)
- **LLM-side**: отказ в формате `ОТКАЗ:[INV-XXX] <объяснение>`

## Формат инвариантов (invariants.json)

```json
[
  {
    "id": "INV-001",
    "category": "editorial",
    "rule": "Запрет на освещение художественной гимнастики",
    "description": "Подробное обоснование запрета...",
    "keywords": ["художественная гимнастика", "гимнастка", ...],
    "active": true
  }
]
```

## Двухуровневая защита

### Layer 1 — Pre-check (без LLM)
```
user input → scan keywords → нарушение найдено?
                                 │ да  → ViolationResult(layer="pre_check")
                                 │       → немедленный отказ, LLM не вызывается
                                 │ нет → Layer 2
```

### Layer 2 — LLM reasoning
```
system prompt = [ИНВАРИАНТЫ] + [роль журналиста]
messages = system + история + новый запрос

LLM ответ:
  "ОТКАЗ:[INV-XXX] ..." → ViolationResult(layer="llm")
  обычный текст         → AgentResponse(allowed=True)
```

## Тесты

```bash
python3 -m pytest test_journalist_agent.py -v
```

**24 теста**:
- `TestInvariant` — `from_dict`, `matches_text`, регистронезависимость
- `TestInvariantStore` — загрузка, pre_check, неактивные инварианты, prompt section
- `TestViolationResult` — фабричные методы, поля
- `TestRefusalPattern` — regex для разбора `ОТКАЗ:[INV-XXX]`
- `TestJournalistAgent` — pre-check блокирует LLM, LLM-отказ парсится,
  история растёт только при разрешённых запросах, prompt injection

## Поведение при конфликте запроса с инвариантом

```
Запрос: "Напиши репортаж о чемпионате по художественной гимнастике"

Layer 1 (pre_check): обнаружено ключевое слово "художественная гимнастика"
→ Немедленный отказ без вызова LLM

Ответ пользователю:
  "Я не могу выполнить этот запрос.
   Причина: запрос нарушает редакционный инвариант [INV-001].
   Правило: Запрет на освещение художественной гимнастики
   Редакция не освещает художественную гимнастику ни в каком виде..."
```

```
Запрос: "Подготовь интервью с Диной Авериной о её карьере"

Layer 1 (pre_check): ключевых слов не найдено → передаём в LLM

Layer 2 (LLM):
  Системный промпт содержит INV-001.
  LLM рассуждает: "Дина Аверина — гимнастка-художница, запрос нарушает INV-001"
  Ответ: "ОТКАЗ:[INV-001] Дина Аверина является спортсменкой по художественной
           гимнастике, что подпадает под инвариант INV-001..."
```
